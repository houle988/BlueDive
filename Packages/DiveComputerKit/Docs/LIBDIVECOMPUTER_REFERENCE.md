## 0. Snapshot identity / provenance (important caveats)

- `UPSTREAM.md` claims upstream commit `9e6c3c83…`, date 2026-09-11, "Version 0.10.0". But `configure.ac:2-5` in this tree says `0.9.0-devel`, while the hand-written `include/libdivecomputer/version.h:16-19` says `DC_VERSION "0.10.0"`, MAJOR 0 / MINOR 10 / MICRO 0. - Possible local divergence: `git log -- libdivecomputer` shows local edits to C sources in the wrapper's history: e.g. commit `61481cd` added `DC_FIELD_AVGDEPTH` layouts to `src/mares_iconhd_parser.c` and `src/oceanic_atom2_parser.c`, DSX decomodel/ppo2/cns/min-max-temp handling in `oceanic_atom2_parser.c`, and the `{"Cressi","Raffaello",…,6,…}` descriptor row (`src/descriptor.c:357`, plus `:943` in the cressi filter). - Removed-upstream files not present: `hw_frog.c/.h` (merged into `hw_ostc3`, `DC_FAMILY_HW_FROG` still exists in `common.h:85` and is routed to `hw_ostc3_device_open(...,1)` at `src/device.c:184-186`). `serial_win32.c` IS present in `src/` (must be excluded on Apple).

## 1. Build integration

### Source list
Authoritative list: `src/Makefile.am:17-100`. Everything in `src/*.c` except `serial_win32.c` (Windows) is part of the library; `serial_posix.c` is the POSIX serial backend (`src/Makefile.am:96-100`). There is no meson/CMake in this tree; only autotools (`configure.ac`, `Makefile.am`). Public headers: `include/libdivecomputer/Makefile.am` (34 headers incl. `version.h`).

Core (required for BLE-only): `version.c descriptor.c iostream.c iterator.c common.c context.c device.c parser.c datetime.c timer.c platform.c ringbuffer.c rbstream.c checksum.c array.c buffer.c ihex.c aes.c hdlc.c packet.c custom.c ble.c` plus ALL backend `*_common.c`, `<vendor>_<model>.c`, `<vendor>_<model>_parser.c` files (device.c/parser.c switch on every family: `src/device.c:120-255`, `src/parser.c:84-213`, so you cannot drop a backend without editing those two files).

### Per-platform exclusion
- Exclude everywhere on Apple: `src/serial_win32.c`, `src/libdivecomputer.rc` (absent anyway), `src/libdivecomputer.symbols` (libtool export list, irrelevant for static linking).
- `usb.c`, `usbhid.c`, `irda.c`, `bluetooth.c` are self-stubbing: without `HAVE_LIBUSB`/`HAVE_HIDAPI`/`HAVE_BLUEZ`/`HAVE_LINUX_IRDA_H`/`HAVE_AF_IRDA_H` they compile to stubs returning `DC_STATUS_UNSUPPORTED` (`src/usb.c:272-319, 442-507`; `src/usbhid.c:37-53`; `src/irda.c:31-42,73,134-256`; `src/bluetooth.c:30-46,73,298-393`). `socket.c/.h` (POSIX sockets) is only used by irda/bluetooth. `atomics_cobalt.c` references `dc_usb_control_t` (a struct from `include/libdivecomputer/usb.h`, `src/atomics_cobalt.c:165,233`) but no `dc_usb_*` functions, so it links even without `usb.c`.
- Verified with `clang -fsyntax-only`: the full set minus `serial_win32.c` compiles cleanly against the **iOS 26 SDK** (only warnings: unused var `src/serial_posix.c:628`, missing-field-initializer `src/suunto_eonsteel_parser.c:1016`). A BLE-only set (also excluding `serial_posix.c usb.c usbhid.c irda.c bluetooth.c socket.c`) also compiles on iOS. `serial_posix.c` uses `termios/fcntl/dirent/fnmatch` which exist on iOS, so including it is harmless; on macOS keep it for USB-serial. `IOKit/serial/ioss.h` is only included if `HAVE_IOKIT_SERIAL_IOSS_H` is defined (`src/serial_posix.c:37-39`) — define it on macOS only (used for non-standard baud rates).
- macOS SDK: compiles with no errors; ~110 `-Wshorten-64-to-32` warnings (size_t→unsigned int) — set `GCC_WARN_64_TO_32_BIT_CONVERSION = NO` for this target or add `-Wno-shorten-64-to-32`.

### Required/optional defines (no config.h is generated; `#include "config.h"` is guarded by `HAVE_CONFIG_H` in 11 files, e.g. `src/context-private.h:25-27`)
Recommended `-D` set for Apple:
- `ENABLE_LOGGING=1` — without it `dc_context_set_logfunc/set_loglevel` are no-ops and all `ERROR/INFO/HEXDUMP` macros compile out (`src/context-private.h:45-59`, `src/context.c:119-125,159-176`). Default loglevel with logging is WARNING and default handler prints to stderr (`src/context.c:84-104,120-121`).
- `HAVE_CLOCK_GETTIME=1` (monotonic timer for log timestamps, `src/timer.c:46,75,118`); alternatives `HAVE_MACH_MACH_TIME_H`+`HAVE_MACH_ABSOLUTE_TIME`; fallback is `gettimeofday`.
- `HAVE_LOCALTIME_R=1 HAVE_GMTIME_R=1 HAVE_TIMEGM=1 HAVE_STRUCT_TM_TM_GMTOFF=1` (`src/datetime.c:33,50,67,122`) — all available on Darwin; without them non-threadsafe `localtime()/gmtime()` fallbacks are used.
- `HAVE_STRERROR_R=1` (`src/context.c:230`) — fallback is non-threadsafe `strerror`.
- `HAVE_PTHREAD_H=1` — only used by `src/usbhid.c:28-30,67,198,208` (mutex around hidapi). Harmless to define.
- `HAVE_IOKIT_SERIAL_IOSS_H=1` macOS only.
- Do NOT define `HAVE_VERSION_SUFFIX` (it makes `src/version.c:28-29,41-42` include a generated `revision.h` defining `DC_VERSION_REVISION`).
- Do NOT define `ENABLE_PTY` (serial pseudo-terminal support, `src/serial_posix.c:48-52`).
- Nothing in the code requires `HAVE_CONFIG_H`.
- `_WIN32` paths are all guarded; `__APPLE__` appears only in `src/serial_posix.c:210` and `src/context.c:287`; `__ANDROID__` in `serial_posix.c`.

### Generated headers
- `include/libdivecomputer/version.h` is generated by autotools from `version.h.in:29-32` (substitutes `@DC_VERSION@`, `@DC_VERSION_MAJOR@`, `_MINOR`, `_MICRO`). The vendored tree already contains a hand-derived `version.h`. On each sync, re-derive from `configure.ac:2-5` (`dc_version_major/minor/micro/suffix`). `dc_version()` returns `DC_VERSION` (`src/version.c:32-46`).
- `config.h`: not needed; pass defines via `OTHER_CFLAGS`/`GCC_PREPROCESSOR_DEFINITIONS`.
- `revision.h`: only with `HAVE_VERSION_SUFFIX`; skip.

### Include paths / modulemap
- Sources include public headers as `<libdivecomputer/xxx.h>` (e.g. `src/iostream-private.h:25-27`) and private headers as `"xxx.h"`, so add `include/` to HEADER_SEARCH_PATHS. Public headers reference each other both as `"common.h"` (e.g. `context.h:25`) and `<libdivecomputer/common.h>` (`iostream.h:26-27`).
- C standard: `configure.ac:65` requires C99 (`AC_PROG_CC_C99`); code uses `//` comments, mixed declarations, `__func__` (`src/context-private.h:39-43`). gnu99/gnu11 fine.
- Flags upstream uses (`configure.ac:181-196`): `-pedantic -Wall -Wextra -Wshadow -Wrestrict -Wformat=2 -Wwrite-strings -Wcast-qual -Wpointer-arith -Wstrict-prototypes -Wmissing-prototypes -Wmissing-declarations -Wno-unused-parameter`. Link `-lm` (`src/Makefile.am:6`; `math.h` used in 2 files).
- 25 source files use `assert()`; in Release (`NDEBUG`) they vanish. Several asserts validate event payloads (`src/device.c:462-480`).
- Modulemap: for Swift you need a clang module. Easiest: a local SPM/Xcode C target whose public headers dir is `include/` with an umbrella header or auto-generated modulemap; or write `include/module.modulemap` exporting `libdivecomputer/*.h` (only the public headers listed in `include/libdivecomputer/Makefile.am`). Swift import gotchas: (a) function-like macros are not imported — `DC_IOCTL_BLE_*` (`ble.h:34-61`) are built from `DC_IOCTL_IOR/IOW` shift macros (`ioctl.h:48-60`) and `dc_descriptor_iterator(iterator)` is a macro (`descriptor.h:50`) — expose these via a thin C shim and call `dc_descriptor_iterator_new(&it, NULL)` directly; (b) `dc_ble_uuid_t` is `unsigned char[16]` (`ble.h:72`) → imports as a 16-tuple; (c) `dc_sample_value_t` is a union with anonymous structs (`parser.h:251-287`) — Swift imports it fine, but the `vendor.data` pointer is only valid during the callback; (d) all callbacks (`dc_logfunc_t`, `dc_event_callback_t`, `dc_cancel_callback_t`, `dc_dive_callback_t`, `dc_sample_callback_t`) are plain C function pointers → `@convention(c)` closures with no captures; pass state through `userdata`.

### Sync friction
- New upstream backends require: new `src/<x>.c/.h`, `<x>_parser.c` files added to the target, plus new `DC_FAMILY_*` in `common.h`, new cases in `device.c`/`parser.c`, new rows+filter in `descriptor.c`. If you use a glob-based SPM target (`sources: ["src"]` with `exclude`), new files are picked up automatically; an Xcode target with explicit file refs will not.
- `version.h` must be hand-regenerated; `UPSTREAM.md` documents the procedure.

## 2. Core API lifecycle

Headers: `include/libdivecomputer/{common,context,iterator,descriptor,iostream,custom,ioctl,ble,device,parser,datetime,buffer,units}.h`.

- `dc_context_new(dc_context_t**)` (`context.h:44-45`, `src/context.c:107-137`); `dc_context_free`; `dc_context_set_loglevel(ctx, DC_LOGLEVEL_NONE..ALL)` (`context.h:33-40`); `dc_context_set_logfunc(ctx, fn, userdata)` where `dc_logfunc_t(context, loglevel, file, line, function, message, userdata)` (`context.h:42`). The message buffer is a per-context 16 KB char array (`src/context.c:46`) — the string pointer is only valid during the callback. `dc_context_get_transports()` returns compiled-in transports and never includes `DC_TRANSPORT_BLE` (`src/context.c:276-306`; `configure.ac:232 transport_ble="no"`) — BLE is always app-provided via `dc_custom_open`.
- Descriptors: `dc_descriptor_iterator_new(&iter, ctx)` (`descriptor.h:46-47`; ctx may be NULL), `dc_iterator_next(iter, &descriptor)` returns `DC_STATUS_SUCCESS` or `DC_STATUS_DONE` (`iterator.h:33-34`, `src/descriptor.c:1009-1028`), `dc_iterator_free`. Descriptors are pointers into a static const table (`src/descriptor.c:97-496`, `:1018-1025`); `dc_descriptor_free` is a no-op (`:1030-1034`) so they may be retained forever. Getters: `get_vendor/get_product` (const char*, static), `get_type` (dc_family_t), `get_model` (unsigned), `get_transports` (bitmask of `dc_transport_t`, `common.h:44-52`).
- `dc_descriptor_filter(descriptor, transport, userdata)` (`descriptor.h:124-125`, `src/descriptor.c:1081-1094`): returns 0 if `transport` not in descriptor's transport mask; returns 1 if descriptor has no filter or userdata==NULL; else calls per-vendor filter. For `DC_TRANSPORT_BLE` the userdata is the advertised device name (`const char*`, `descriptor.h:120`). `dc_filter_internal` (`:641-654`) returns 1 if key==NULL, else true if any entry matches, else `count==0`.

## 3. Custom I/O stream

`dc_custom_open(&iostream, ctx, transport, const dc_custom_cbs_t *callbacks, userdata)` (`custom.h:61-62`, `src/custom.c:73-96`): copies the callback struct by value; pass `DC_TRANSPORT_BLE` so backends take BLE code paths (they test `dc_iostream_get_transport()`; e.g. `src/shearwater_common.c:164-165,258-265`, `src/hw_ostc3.c:451,473`). Any NULL callback is treated as success/no-op (`src/custom.c:98-261`), and `dc_iostream_*` wrappers also no-op on NULL vtable slots (`src/iostream.c:79-312`).

Callback semantics (`custom.h:33-49`, contract documented in `iostream.h`):
- `set_timeout(ud, int ms)`: <0 block forever, 0 non-blocking, >0 wait up to ms for the full requested read (`iostream.h:95-124`). Backends set 1000–6000 ms on BLE (e.g. shearwater 3000 `src/shearwater_common.c:86`, eonsteel 5000 `:647`, cressi goa 5000 on BLE `src/cressi_goa.c:405`, seac 6000 `src/seac_screen.c:349`, uwatec 5000 `src/uwatec_smart.c:492`, oceans_s1 4000, divesystem 1000, mclean 1000, deepblu 1000). Honour it: your read should wait for a notification up to that long.
- `set_break/set_dtr/set_rts(ud, unsigned value)`, `configure(ud, baud, databits, parity, stopbits, flowcontrol)`: called by many backends even on BLE (e.g. `src/shearwater_common.c:79`, `src/cressi_goa.c:397,413,420`, `src/mares_iconhd.c:594,608,615`) — return `DC_STATUS_SUCCESS` (or leave NULL).
- `get_lines(ud, unsigned*)`, `get_available(ud, size_t*)`: return SUCCESS with 0 (or NULL).
- `poll(ud, int ms)`: return SUCCESS if data available, `DC_STATUS_TIMEOUT` on timeout (`iostream.h:198-226`). Used by few backends (mares_nemo/memomouse, not BLE ones); may be NULL (then returns SUCCESS).
- `read(ud, void *data, size_t size, size_t *actual)`: see packetization below. Return `DC_STATUS_SUCCESS` with `*actual` bytes (may be < size), `DC_STATUS_TIMEOUT` if nothing arrived within the timeout, `DC_STATUS_IO` on link failure, `DC_STATUS_CANCELLED` if you want to abort. **Never return SUCCESS with 0 bytes**: `dc_packet_read` loops until `size` bytes are gathered (`src/packet.c:203-236`) and `dc_hdlc_read` loops until a frame END (`src/hdlc.c:211-267`), so an empty success spins.
- `write(ud, const void*, size_t, size_t *actual)`: write the whole buffer as one BLE write (backends split into ≤20-byte or ≤244-byte chunks themselves via `dc_packet_open(..., osize)` or manual chunking). Return SUCCESS with `*actual = size`.
- `ioctl(ud, unsigned request, void *data, size_t size)`: see BLE ioctls. Return `DC_STATUS_UNSUPPORTED` for unknown requests (several backends tolerate this: `src/oceanic_atom2.c:817-823`, `src/pelagic_i330r.c:391,439`). `dc_iostream_ioctl` validates size (`src/iostream.c:238-244`): variable-size requests accept any size.
- `flush(ud)`: return SUCCESS. `purge(ud, direction)`: discard any queued incoming notifications (called at open by nearly all backends, e.g. `src/shearwater_common.c:94`); return SUCCESS.
- `sleep(ud, ms)`: block the calling thread for ms (called a lot: `src/cressi_goa.c:124-125` sleeps 2000 ms before each BLE command!). If NULL nothing sleeps, which breaks protocols that rely on inter-packet delays — implement with `usleep`/`Thread.sleep`.
- `close(ud)`: called from `dc_iostream_close`; release the peripheral.

### BLE ioctls (`include/libdivecomputer/ble.h`)
- `DC_IOCTL_BLE_GET_NAME` (`:34`): variable-size read; fill `data` with the advertised name (NUL-terminated if room). User: **Oceanic/Aqualung Atom2 BLE** handshake (`src/oceanic_atom2.c:815-835`) needs ≥8 chars (`FQ001124`-style; first 2 chars = model, 6 digits = serial used to derive a passphrase); `UNSUPPORTED` is tolerated with a warning (download likely fails).
- `DC_IOCTL_BLE_GET_PINCODE` (`:41`): NUL-terminated string; buffer is 7 bytes (`src/pelagic_i330r.c:420-428`). User: **Pelagic i330R / Apeks DSX** — you must prompt the user for the 6-digit PIN shown on the dive computer, synchronously, inside this callback.
- `DC_IOCTL_BLE_GET_ACCESSCODE` / `SET_ACCESSCODE` (`:48-49`): 16-byte array (`src/pelagic_i330r.c:72,390,438`). User: Pelagic i330R/DSX. Persist per-peripheral (Keychain/UserDefaults); return `UNSUPPORTED` or zeros if none (`:391,405-406`). Flow: GET → try access → on NOACCESS, GET_PINCODE → request access code → SET_ACCESSCODE, up to MAXRETRIES=3 (`:396-443`).
- `DC_IOCTL_BLE_CHARACTERISTIC_READ` / `WRITE` (`:60-61`): `data` = 16-byte `dc_ble_uuid_t` followed by payload; `size` = 16 + payload. User: **Cressi Goa family** reads 3 characteristics `6E400003/4/5-B5A3-F393-E0A9-E50E24DC10B8` (5, 2, 2 bytes) for version info (`src/cressi_goa.c:475-513`). Implement by finding the characteristic by UUID on the connected peripheral and doing a GATT read; copy result after the UUID. `dc_ble_uuid2str/str2uuid` helpers in `src/ble.c:32-97`.
- No backend uses `CHARACTERISTIC_WRITE` currently. No other BLE ioctls exist in this version.

### Packet/MTU expectations per family (what `read` is asked for)
- Several backends wrap your stream in `dc_packet_open(base, isize, osize)` (`src/packet.h`, `src/packet.c:78-121`): reads are issued to your callback with `size == isize` and whatever you return (one notification, `len ≤ isize`) is cached and doled out; writes are chunked to `osize`. Used: hw_ostc3 (244/20, `src/hw_ostc3.c:474`), mares_iconhd FIXED-mode models (244/20, `src/mares_iconhd.c:584`; Sirius-class "VARIABLE" models use raw stream, `:580`), divesystem_idive (244/244, `:175`), mclean_extreme (244/244, `:412`), seac_screen (244/244, `:332`).
- `dc_hdlc_open(base, isize, osize)` (`src/hdlc.c:83-139,201-280`): frames delimited by 0x7E, reads your stream in `isize` chunks. Used: suunto_eonsteel BLE (20/20, `src/suunto_eonsteel.c:638`), divesoft_freedom (244/244, `:315`).
- Direct reads expecting **one whole notification per read** (`*actual` = notification length): shearwater (buffer 514 bytes `BLE_MTU_MAX`, `src/shearwater_common.c:260-273`; writes are 20-byte frames with a 2-byte [nframes, idx] header on protocol V1, header omitted for Perdix 3 "V2", `:164-187`), oceanic_atom2 (20-byte packets `0xCD` framing, `src/oceanic_atom2.c:533-628`), uwatec_smart (reads 256 bytes `DATASIZE_RX+1`, `src/uwatec_smart.c:319-327`; BLE writes `buf+1` without the leading report-id byte `:300-301`; handshake skipped on BLE `:432-434`), cressi_goa (reads `SZ_DATA` chunks and accumulates `src/cressi_goa.c:234-246`; then reads 16 "EOT xmodem" bytes `:298-312`), deepsix (packet up to 260), deepblu (variable), oceans_s1 (xmodem 3+128+2), halcyon (2+256+1), divesoft (6+MAXDATA+2 via HDLC), pelagic_i330r (via oceanic_common).
- Practical rule for the Swift side: queue incoming notifications; `read(size)` returns the oldest notification (truncated to `size` if larger — but better choose MTU so it never is), waiting up to the timeout; if a notification is larger than `size` keep the remainder for the next read. Max requested sizes are 514 (shearwater) and 256 (uwatec) so a 512-byte ATT MTU is fine; MTU 20 works for all (they chunk).
- Many backends issue `sleep` + `purge` right after open (`src/hw_ostc3.c:498-499`, `src/divesystem_idive.c:199-200`) — purge must drop stale notifications.

### API-shape notes vs. other versions (sync hazards)
- Time is already ms in this version (older 0.6-era was seconds). `dc_sample_value_t.ppo2` is already a struct `{sensor,value}` (older versions had plain `double ppo2`). `deco` already has `tts`. `dc_tank_t` and `dc_gasmix_t` already have `usage`. `dc_decomodel_t` and `DC_FIELD_DECOMODEL`/`DC_FIELD_LOCATION`/`DC_SAMPLE_LOCATION` exist. `dc_parser_new` takes data at creation (no `set_data`). `DC_SAMPLE_TTS`, `DC_FIELD_STRING`, `dc_parser_set_data`, `dc_descriptor_get_filter`, `dc_device_version` do not exist here — if a future upstream adds/changes any, Swift code compiled against the imported header will break at compile time (good) but enum **renumbering** (e.g. inserting a new `DC_SAMPLE_*` or `DC_FIELD_*` in the middle) would silently change raw values if you persist them — never persist raw enum ints.

## 5. Events and cancellation (`device.h:36-71`, `src/device.c:457-519`)
- `DC_EVENT_WAITING` (data NULL): waiting for user action on the device; emitted only by mares_nemo/uwatec_aladin/memomouse (serial) — not BLE.
- `DC_EVENT_PROGRESS` → `dc_event_progress_t {unsigned current, maximum}`; initializer `{0, UINT_MAX}` (`src/device-private.h:36`), so maximum may be UINT_MAX until the backend knows the size; `maximum` is asserted non-zero and ≥ current. Emitted frequently (per packet).
- `DC_EVENT_DEVINFO` → `dc_event_devinfo_t {unsigned model, firmware, serial}`; cached in the device and used by `dc_parser_new` for the model (`src/parser.c:229-230`). Encoding is backend-specific: shearwater `model` = hardware model id, `serial` = 32-bit BE of 4 serial bytes (`src/shearwater_petrel.c:204-207`); eonsteel serial = decimal from 16-char string, firmware 32-bit (`src/suunto_eonsteel.c:717-719`); oceanic model = 2-byte BE from version string, serial BCD/bin (`src/oceanic_common.c:250-255`); hw_ostc3 (`:803-806`); uwatec (`:623-626`); mares (`firmware` always 0, `:810-812`); pelagic (`firmware` 0, `:590-596`); oceans_s1 (`serial` 0, `:575-578`); divesoft/halcyon/deepsix/deepblu/divesystem/seac/mclean as listed. Format strings for display are app responsibility.
- `DC_EVENT_CLOCK` → `dc_event_clock_t {unsigned devtime; dc_ticks_t systime}` (device clock vs host `dc_datetime_now()` epoch seconds); emitted by uwatec_smart (`src/uwatec_smart.c:616-619`) and a few serial backends; cached and passed to parser via set_clock (only Reefnet/memomouse parsers use it).
- `DC_EVENT_VENDOR` → `{const unsigned char *data; unsigned size}` raw version/ID block; pointer valid only during callback. Emitted by many backends (`grep DC_EVENT_VENDOR`: cressi_goa `:568`, mares_iconhd `:798,1165`, oceanic_common `:246`, divesystem `:469`, halcyon `:467`, seac `:501,540`, suunto_common2, etc.).
- Events are delivered synchronously on the thread running `dc_device_open/foreach` and only if the bit is in the mask passed to `dc_device_set_events` (`src/device.c:497-505`). DEVINFO/CLOCK are cached regardless of mask (`:485-495`).
- Cancellation: `dc_cancel_callback_t(userdata) -> int` (non-zero = cancel). Backends poll `device_is_cancelled()` at packet boundaries (`src/device.c:509-519`; 33 backends; e.g. `src/shearwater_common.c:369-370`, `src/oceanic_atom2.c:676-677`, `src/mares_iconhd.c:238-239`) and return `DC_STATUS_CANCELLED`. Granularity is one protocol transaction, so cancellation latency ≈ one read timeout worst case. Additionally your custom `read`/`write` can return `DC_STATUS_CANCELLED` to abort immediately (status propagates unchanged — `src/packet.c:212-213`). Returning 0 from the dive callback stops the download gracefully with `SUCCESS`.

## 6. Status codes (`common.h:29-42`)
`SUCCESS 0, DONE 1 (iterator end), UNSUPPORTED -1, INVALIDARGS -2, NOMEMORY -3, NODEVICE -4, NOACCESS -5 (e.g. i330R PIN/access denied src/pelagic_i330r.c:416), IO -6, TIMEOUT -7, PROTOCOL -8 (bad checksum/framing), DATAFORMAT -9 (parser data invalid), CANCELLED -10`. Your custom stream should return TIMEOUT when no notification arrives within the set timeout (not IO) because backends retry on TIMEOUT/PROTOCOL but abort on IO: retry loops `if (rc != DC_STATUS_TIMEOUT && rc != DC_STATUS_PROTOCOL) return rc; if (nretries++ >= MAXRETRIES) return rc;` in oceanic_atom2 (`:772-789`, MAXRETRIES 2, growing inter-packet delay), mares_iconhd (`:414-434`, 4, with 1 s sleep + purge), divesystem_idive (`:412`, 9), seac_screen (`:292`, 4), cochran, cressi_edy/leonardo, hw_ostc (9), liquivision, oceanic_veo250/vtpro, reefnet, sporasub, suunto_common2 (2), mares_common; mclean (`:173`) and tecdiving tolerate TIMEOUT in a loop (MAXRETRIES 14); pelagic retries access (3); halcyon MAXRETRIES 3. **No retry on TIMEOUT**: shearwater, suunto_eonsteel, hw_ostc3, uwatec_smart, cressi_goa, divesoft, deepsix, deepblu, oceans_s1 — a single lost notification fails the download, so the app may want to retry the whole `dc_device_open+foreach` with fingerprint set. `dc_status_set_error` keeps the first error (`src/common.c:27-34`). Built-in transports return TIMEOUT from `socket.c/serial_posix.c/usbhid.c/usb.c` only.

## 7. Threading
- No locking anywhere in the core (context/device/parser are plain malloc'd structs; `grep pthread_` hits only `usbhid.c`). The library is reentrant per object: separate contexts/devices/parsers may be used from different threads concurrently, but a single `dc_context_t` (shared 16 KB log buffer `src/context.c:46,198`) or `dc_device_t` must not be used from two threads at once. The descriptor table is static const and safe to read concurrently.
- `dc_device_open`, `dc_device_foreach`, `dc_device_timesync`, `dc_device_close` are fully synchronous and blocking: they call your `read` which must block (sleep/condition-wait) until a notification arrives or timeout. Therefore run the whole download on a dedicated background thread (not the main thread, not a Swift cooperative-pool task that could starve) and bridge CoreBluetooth callbacks (which arrive on your CB queue) into a thread-safe queue + semaphore/condition. Do not call CoreBluetooth synchronously from inside the callbacks on the CB delegate queue. `dc_iostream_sleep` (`src/platform.c:35-53`, `nanosleep`) blocks the calling thread.
- All callbacks (events, cancel, dive, samples, log) fire on the thread that called the API.

## 8. Fingerprints
`dc_device_set_fingerprint` stops enumeration when a dive whose fingerprint equals the stored one is reached — the backend `break`s before calling the callback, so dives are delivered newest-first and the fingerprint of the FIRST (newest) dive received should be persisted.
- Shearwater Petrel/Predator: 4 bytes = dive bytes 12..15 (`src/shearwater_petrel.c:343`, `src/shearwater_predator.c:266`), compared against manifest entry bytes 4..7 (`:284`). size must be 4 (`:134-145`).
- Suunto EON Steel: 4 bytes = first 4 bytes of dive data (`src/suunto_eonsteel.c:793`), size 4.
- HW OSTC3: 5 bytes at `layout->fingerprint` offset of the header (`src/hw_ostc3.c:124,1011`), size 5.
- Uwatec/Scubapro Smart: 4 bytes at dive offset 8 (`src/uwatec_smart.c:731,541-545`).
- Oceanic/Aqualung Atom2 + Pelagic i330R: size = `layout->rb_logbook_entry_size` (`src/oceanic_common.c:168-171`): 8 for default/oc1 layouts, 16 for Pro Plus X / i770R / A300CS-family (Sage, Beacon) / i450T (`src/oceanic_atom2.c:134,262,374,390,406,422`), 64 or 512 for i330R/DSX (`src/pelagic_i330r.c:108,124`); fingerprint = the logbook entry prepended to the dive data (`src/oceanic_common.c:649`). Size depends on the detected model, so query it from the callback `fsize` rather than hardcoding.
- Cressi Goa: 6 bytes (`FP_SIZE` `src/cressi_goa.c:55`) at `headersize + conf->dive_fp_offset` (`:686`).
- Mares Icon HD: 10 bytes default, 4 for Genius-layout models (Genius, Quad Ci, Quad 2, Sirius L, Puck 4… `src/mares_iconhd.c:576,686`); position `data+8` or per-layout (`:1018,1146`). Set-fingerprint size is validated against the model-dependent size (`:734`), so only set it after open.
- Divesystem/Ratio: 4 bytes at offset 7 (`:581`, `:99`). McLean: 4 bytes at `SZ_CFG` (`:613`). Seac: 4 bytes (`FP_SIZE` `:72`, `:773`). Deep Six: 6 (`:41,458`). Deepblu: 6 (`:50,515`). Halcyon: 4 (`:64,560`). Divesoft: 20 (`FINGERPRINT_SIZE` `:43`). Oceans S1: 8 (`SZ_FINGERPRINT` `:46`).
- Passing size 0 clears the fingerprint (all `set_fingerprint` impls memset to 0 when size==0); wrong size → `DC_STATUS_INVALIDARGS`. Store fingerprints keyed by (family, model, serial).

## 10. Risks for manual upstream syncs
1. Local divergence: as noted in §0 the tree may carry non-upstream edits. A naive file copy will silently drop them; a naive skip will miss upstream fixes. Maintain a patch series (or keep the tree pristine).
2. `version.h` is hand-maintained and already inconsistent with `configure.ac` (0.9.0-devel vs 0.10.0); `dc_version()` reports whatever you write there.
3. New source files upstream (new backend = 3 files) must be added to the target; `device.c/parser.c/descriptor.c/common.h` change together. Watch `src/Makefile.am` diff as the authoritative file list.
4. Enum additions/renumbering in `common.h` (`dc_family_t` values are `(N<<16)+k`, stable) and `parser.h` (`dc_sample_type_t`, `dc_field_type_t` are sequential — new entries appended at the end so far, but any mid-insertion renumbers). Swift `switch` over imported C enums needs `default` cases to survive additions.
5. Struct layout changes in `dc_sample_value_t`/`dc_tank_t`/`dc_gasmix_t`/`dc_decomodel_t` would change Swift imported types — compile-time breaks, but code keyed on field *presence* (e.g. `usage`) must be re-checked.
6. Behavioural changes in packet sizes/`dc_packet_open` parameters (e.g. 20→244) alter what `read` is asked for; keep the custom stream generic (notification queue, size-agnostic).
7. New BLE ioctls may appear in `ble.h` (currently 6); unknown requests must return `UNSUPPORTED` so new backends degrade gracefully, and your C shim constant list must be regenerated.
8. `descriptor.c` filter name lists change often (new prefixes/models); the BLE scan allow-list in the app must be regenerated from `g_descriptors` + filter functions rather than hand-copied (consider calling `dc_descriptor_filter` at runtime on the advertised name instead of duplicating patterns in Swift — the only inputs are transport + name, so this is cheap and always in sync).
9. `assert()`s in debug builds will crash on protocol anomalies in event payloads (`src/device.c:462-480`) — keep them (they catch backend bugs) but don't ship `-UNDEBUG` builds.
10. Windows-only/`serial_win32.c` and future platform files must be re-excluded after each copy; `.rc`/`.symbols` are irrelevant.
11. Warnings: Xcode's default `-Wshorten-64-to-32` produces ~110 warnings; `-Werror` on this target will break on each sync — scope warning flags per-target.
